# Hello Coder 技术选型文档

> 多工具 Web 平台：Kafka / Elasticsearch / Redis 客户端。后端 Go 单二进制，前端为嵌入式静态 HTML。

## 1. 项目定位

| 项 | 说明 |
| --- | --- |
| 形态 | Windows 本机独立窗口（WebView2）；Linux/内网以浏览器访问同一套 Web UI |
| 后端 | Go 单体服务，提供 REST API，静态前端由同一进程托管 |
| 配置存储 | SQLite：主表 `user`；工具表 `kafka_conn` / `es_conn` / `redis_conn` |
| 认证 | 注册/登录 + JWT（Bearer） |
| 当前范围 | Kafka（连接、Topic、生产/消费预览）；ES（连接、索引、文档）；Redis（连接、Key 浏览/读写） |

## 3. 选型说明

### 3.1 为什么用 Gin

- 生态成熟、中间件齐全（CORS、恢复、限流等）
- 适合工具类 API，学习与维护成本低
- 与后续扩展（ES、Redis 等模块路由分组）契合

### 3.2 为什么用 SQLite + modernc（无 CGO）

- 单文件数据库，适合「连接配置」这类轻量数据
- `modernc.org/sqlite` 无需 CGO，Windows / Linux / macOS 交叉编译简单
- 通过 GORM 统一模型与迁移，后续若换 Postgres 改动面小

### 3.3 为什么用 Sarama

- 社区使用广泛，支持 Kafka 管理能力（Topic、消费组、Offset 等）
- 生产/消费 API 完善，适合做运维向客户端工具
- 备选：`segmentio/kafka-go`（更偏简洁）、`twmb/franz-go`（性能向）；首期以 Sarama 为主，文档中锁定，避免混用

### 3.4 为什么静态前端 + 嵌入资源

- 开发期：`HELLO_CODER_STATIC_DIR=./web/static` 直接读磁盘，改 HTML/JS 刷新即生效
- 发布期：`go:embed` 嵌入 `web/static`，单二进制部署，无需 Node 构建

## 4. 功能范围

### 4.1 连接配置（SQLite）

- 增删改查 Kafka 集群连接：名称、Brokers、协议（PLAINTEXT / SASL / SSL）、认证信息
- 敏感字段：传输 RSA-OAEP，落库 AES-GCM（无需 HTTPS 证书）
- 连接测试（探测 Brokers / 获取集群元数据）

### 4.2 集群浏览

- Topic 列表（含分区数、副本数等基础信息）
- 消费组列表与成员概览
- Topic 详情：分区、Leader、ISR（视权限与版本能力）

### 4.3 消息操作

- 生产消息：指定 Topic / Key / Value / Header（可选分区）
- 消费预览：按 Topic + 分区 + Offset 或从 Latest/Earliest 拉取有限条数（工具向，非常驻消费者）

### 4.4 Elasticsearch / Redis（已落地）

- ES：连接管理、集群概览、索引结构、文档检索与批量操作
- Redis：连接管理（单点 / 集群 / 哨兵）、INFO、Key 扫描与读写

### 4.5 后续迭代

- Schema Registry、ACL 管理、消息搜索落库、多租户权限

## 5. 目录结构（已落地）

按「可插拔工具模块」组织，后续加工具只需新增 `internal/modules/<name>` 并在路由注册。

```text
hello-coder/
├── cmd/server/                 # 进程入口
├── internal/
│   ├── app/                    # 组装配置、DB、HTTP
│   ├── config/                 # 进程配置（端口、数据目录）
│   ├── middleware/             # 通用中间件
│   ├── model/                  # 用户与各工具连接模型
│   ├── modules/
│   │   ├── module.go           # Module 接口 + Deps
│   │   ├── auth/               # 注册 / 登录
│   │   ├── kafka/              # Kafka 客户端
│   │   ├── es/                 # Elasticsearch 客户端
│   │   └── redis/              # Redis 客户端
│   ├── secret/                 # 传输 RSA / 落库 AES
│   ├── desktop/                # Windows WebView2 窗口
│   ├── response/               # 统一 JSON 响应
│   ├── server/                 # Gin 路由挂载与 HTTP Server
│   └── store/                  # SQLite / GORM
├── web/                        # 静态 HTML + ES modules（go:embed）
├── data/                       # 运行时数据（gitignore）
├── docs/
├── scripts/                    # 构建脚本
├── go.mod
└── README.md
```

扩展约定：实现 `modules.Module`（`Name` + `Register`），在 `internal/server/router.go` 的模块列表中追加即可。

## 6. API 前缀约定（草案）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| CRUD | `/api/v1/kafka/conns` | Kafka 连接（创建人为当前用户） |
| POST | `/api/v1/kafka/conns/:id/ping` | 可用性检测 |
| GET | `/api/v1/kafka/conns/:id/topics` | Topic 列表 |
| GET | `/api/v1/kafka/conns/:id/topics/*topic` | Topic 详情（分区 / Brokers / 消费组） |
| DELETE | `/api/v1/kafka/conns/:id/topics/*topic` | 删除 Topic |

具体请求/响应字段在实现 API 时再补 OpenAPI 或接口表。
